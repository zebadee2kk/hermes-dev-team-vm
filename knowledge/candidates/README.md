# Technology candidates

One YAML record per candidate. Candidate status is deliberately separate from the compiled wiki: a useful concept can be documented without being approved into the running stack.

Lifecycle:

`observed -> triaged -> sandbox_tested -> probation -> promoted | rejected`

A promoted candidate must satisfy `evaluate_promotion()` and the policy in `config/knowledge-system.yaml`. Popularity, novelty, social engagement and model-written enthusiasm are not promotion evidence.
